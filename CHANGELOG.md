## [Unreleased]

### Added
- `screenscribe` (v0.6.0, marketplace 1.26.0): **library maintenance — `index`, `search`, `prune`.**
  - **`index`** — every bundle in the library: id, frames on disk, size, length, last read, title, with a reclaimable-bytes total. `--json` for the machine-readable form, which carries the URL each bundle was built from.
  - **Naming a video.** Every command that takes one — `window`, `artifact`, `prune --id`, `search --id` — accepts the id, the URL in any shape, or any words from the title or channel, matched case-insensitively. An exact id beats a title that happens to mention it, and an ambiguous name is refused with the candidates listed rather than guessed, because `prune` deletes and a guess there deletes the wrong video. `index` needs no maintenance: it scans the bundle root, so a new `build` appears in it with no bookkeeping and there is no list file to fall out of step.
  - **`search <term>`** — one grep across every scribe. Each hit prints the timestamp and `frames/HH-MM-SS.jpg` for the frame that was on screen when that line was spoken (the last frame sampled at or before the cue, because dedupe means cues rarely land on one exactly). `-C N` for surrounding cues, `--id` to restrict, `-e` for a regex, `--limit` to bound the output. Fixed-string and case-insensitive by default.
  - **`prune`** — removes bundles: frames, scribe, directory. Selectors do not combine, first given wins: `--id`, `--older-than DAYS`, `--keep N`, `--over SIZE`, defaulting to `--over 2G` with least-recently-read pruned first. **Dry run unless `--yes`.**
  - **`prune --frames-only`** — the cache-eviction mode. A bundle is two things with a 2000:1 size ratio: the scribe (`BUNDLE.md` + `meta.json`, tens of KB, holding the transcript and the URL it was built from) and the frames (~5 MB per minute). Measured across three bundles: 156 KB of scribe against 300 MB of frames, 0.05%. So evicting only the frames reclaims essentially all of the disk while the video stays searchable and rebuildable from its URL.
  - v0.4.0 had these two the wrong way round — `prune` evicted frames and `--purge` removed the bundle — which inverted what "prune a scribed video" means. Corrected here, one commit later; `--purge` is gone.
  - `window` and `artifact` now record a read (`.last_used`, so LRU reflects reading rather than only building) and, on a pruned bundle, exit with the literal `build <url>` command that restores it — recoverable failure, named as one, instead of an empty span that reads as "nothing was on screen".
  - Frame-timestamp parsing was duplicated across `emit_window` and `frames_in_span`, which is how the artifact filter drifted from the window filter in v0.3.0. Search would have been a third copy; all three now go through one `bundle_frames` reader.
  - 49 tests (155 -> 204), including the two defects found by running the new code against the author's real library: `.DS_Store` sitting in the bundle root (a bundle is now a directory holding a readable meta.json *object* — nothing else is listed, and emphatically nothing else is deleted), and `prune --keep 0` re-selecting an already-stripped bundle, printing bytes freed that no eviction produced and never settling on "nothing to prune".

### Fixed
- `screenscribe` (v0.3.1, marketplace 1.23.1): **round-1 code review of the artifact subsystem — one HIGH and six MEDIUM, all remediated.** That code shipped unreviewed in v0.1.0 and had been carried as known debt through two releases; this is the first time anyone looked at it, and every finding below was reproduced by execution before being fixed.
  - **HIGH — HTML injection via the video title.** `build_artifact` substituted the title into `<title>__TITLE__</title>` by raw string replacement. A bundle whose title is `</title><script>alert(document.domain)</script>` produced that script tag live in the output, in a page the skill then tells you to publish. The title is network-derived third-party metadata from the same source that already required `safe_dest()` after a real path traversal. Now escaped with `html.escape(..., quote=True)`. The JSON payload never needed it — the template assigns every field with `textContent` and `</` is neutralized — so this was the one place raw substitution survived.
  - **MEDIUM — narration inside the span silently dropped.** Rows paired cues with `f.ts <= c.start < nxt`, so anything spoken before the *first surviving frame* matched no row and never reached the page. Reproduced: frames at 10/15/20s, span 0-30, narration at t=3 absent with no warning. Row 0 now reaches back to the span start. This is content loss on an artifact whose only purpose is pairing narration with the screen it was spoken over.
  - **MEDIUM — the link filter ate the technical links it exists to protect.** `LINK_NOISE` substring-matched the whole URL: `"amazon."` dropped `docs.aws.amazon.com/lambda/...` and `"x.com/"` dropped `phoenix.com/engineering/blog`. Replaced with `NOISE_HOSTS` matched against the parsed hostname (exactly or as a subdomain), `NOISE_HOST_PATHS` for promotional paths on hosts that also serve real content — which is why `amazon.com` is a path rule and `docs.aws.amazon.com` now survives — and `NOISE_MARKERS` for unambiguous substrings.
  - **MEDIUM — `window_header_estimate` was an unbound name gating a dead branch.** SKILL.md deleted the sentence that bound the term but kept the conditional consuming it, and the branch was unreachable regardless: `emit_window` exits on the size guard *before* printing the header, so that estimate is unobservable without `--force`, which SKILL.md never mentioned. Replaced with the signal the script actually emits, and with an instruction not to reach for `--force`.
  - **MEDIUM — "**any** timestamp maps to `frames/HH-MM-SS.jpg`" was false**, in SKILL.md and in the BUNDLE.md banner. `dedupe` deletes visually-identical frames: measured on bundle `XV2PAHWnJN0`, 339 frames over 415 seconds, so 76 seconds have no file at all; `--fps 2` additionally produces `HH-MM-SS_02.jpg`, which no timestamp derives. The consequence was a wrong inference rather than a failed read — a missing frame means the screen did not change, but a model promised every timestamp resolves reads absence as "nothing was on screen", which is the exact conclusion this plugin exists to prevent. Both files now state the rule and its limit.
  - **MEDIUM — the grep recipes named `BUNDLE.md` with no resolvable path.** Stage 2 makes grep the primary read path, but bundles live at `<root>/<video_id>/` and never in the working directory, so the commands failed on every invocation. `$BUNDLE` is now bound from the absolute path `build` prints on its `[done]` line.
  - **MEDIUM — the untrusted-content guard named a subset of the bundle.** It enumerated "frames and transcript"; `build_bundle` also writes the raw author description verbatim plus 25 extracted URLs, and this release had replaced a bounded read with "read it or grep it" pointing at the section where that description sits. The guard now covers the whole artifact, description and links included.
  - Also fixed from the same review: `$PY` is validated with `[ -x ]` after binding (a noisy `python3` shim would otherwise corrupt it silently three sections later), the first-run bootstrap timeout is called out, the `./bundles/<id>` window form Stage 1 still recommends was restored, costume-prose and a duplicated remedy were collapsed while restoring the dropped `batch in parallel` hint, "the scribe" stopped naming three different things, and README.md's stale venv-then-fallback paragraph was corrected.
  - 8 regression tests (147 -> 155), one per defect, each covering a failure reproduced before it was fixed.
- `screenscribe` (v0.2.0, marketplace 1.22.0): **perceptual dedupe was a no-op on any video with a webcam overlay, and the frames it kept were unreadable in bulk.** Measured on the 58-minute podcast from the previous entry: whole-frame phash retained **99.8%** of the screen-share frames (944 of 946). The cause is not threshold calibration — it is that the metric was measuring the wrong pixels. Two circular face cams sit in the bottom corners of *every* frame, screen-share frames included, and a face moves every single frame, so each one hashed as a new screen forever. The 89.99% retention flagged last release was the same bug seen from the outside. `dedupe` now hashes `HASH_BOX` (the centre 72% x 66%) instead of the whole frame; the full frame is still what gets saved and read, only the similarity decision ignores the corners. Same input: 946 -> 520 frames. `--whole-frame-hash` restores the old behaviour for footage whose edges are the content. The retention warning drops 0.90 -> 0.85 and no longer recommends `--crop`, which never helped here: `--crop` is applied in ffmpeg's filter chain and so discards those pixels permanently, and the cams are overlaid *on* the screen-share rather than beside it.
- Verified by measurement, not by reading: a synthetic static screen with block noise in the excluded corner scores **54-88** apart on a 256-bit whole-frame hash (threshold 10) and **exactly 0** apart on the centre hash. An earlier version of that fixture used scattered single pixels and did not reproduce the bug at all — phash downscales to 64x64 before its DCT, and single pixels average away to nothing at that size.
- `screenscribe` (v0.2.0): **the transcript was a paraphrase, not a transcript.** YouTube publishes two English tracks for an auto-captioned video: `en-orig` ("English (Original)") is the ASR of what was actually said, and `en` is a processed rendering of it. Requesting `en` first returned prose the speaker never spoke — disfluencies and `>>` speaker markers stripped, connectives inserted ("Of course, if you work alone"), acronyms helpfully expanded ("because of what we did with reinforcement learning (RL)" for "because of what we've done during RL"), "publicly traded companies" reworded to "public companies", "series B plus fintech companies" to "fintech startups of Series B and above". Measured on the same 58-minute video: 3333 cues and 61,556 characters against the original's 1980 cues and 71,446 — more cues, 14% less text, and none of it verbatim. A transcript that rewrites the speaker is derived evidence, which is precisely what this plugin refuses to cite and why `--gemini` was cut before release. Languages are now tried `en-orig` -> `en` -> `en-US`, and a test asserts that order. Videos with author-uploaded subtitles have no `en-orig` and fall through unchanged.
- `screenscribe` (v0.2.0): **a rate-limited subtitle fetch no longer destroys the video download.** yt-dlp runs `_write_subtitles` *before* the media download inside `process_info`, so `HTTP 429` on the caption endpoint raised `DownloadError` and killed the entire run — twice in a row on the 58-minute video. YouTube rate-limits `timedtext` far harder than the media endpoint, and the old options asked for three language variants of both the manual and automatic track: up to six hits on the tenderest endpoint per build. Subtitles now download in their own pass after the video, one language at a time stopping at the first that lands, with three attempts and 5s/10s backoff; a failure warns and continues, and the pipeline already handled a bundle with no cues. A transcript is worth much less than the 587 MB video it annotates.
- `screenscribe` (v0.2.0): **the frame classifier hid real content, and now declines to judge when it cannot.** Introduced earlier in this same unreleased version and caught by running the real `build` on a second video rather than by reading the code: on a git tutorial that draws diagrams over blurred b-roll, a **git branch diagram** (Feature/Main with commit nodes) scored 0.1418 and was filed as camera footage — the exact failure this tool exists to prevent. Content drawn over photographic backgrounds lands mid-scale, and there is no valley to cut at: within +/-0.05 of the threshold sit 0.19% of the podcast's frames but 6.89% of that screencast's, a 36x difference. `separates()` now measures that occupancy before the classification is trusted, and when the frames do not fall into two groups `build` says so, records nothing, and every frame is kept and shown — the same path a bundle built before classification existed already took. Otsu's method was measured and rejected for choosing the cut: it picks 0.41 on the podcast, which files a hand-verified screen at 0.243 as camera footage.
- `screenscribe` (v0.2.0): **the shareable page carried the same two defects, in its own copy of the logic.** `pick_for_display` hashed the whole frame, so corner webcams held every frame alive exactly as they did in `dedupe` — 2072 of 2771 frames survived the display cull and the page came out at **94.43 MB against a 16 MB cap**. It now hashes `HASH_BOX` too. Separately, `build_artifact` predated frame classification and never consulted it, so a page spent its byte budget on webcam stills; it now applies the same read-time filter `window` does, with the same fallback to every frame when a span holds no screen. Together: 94.43 MB -> 17.98 MB, 2072 screens -> 377, on the same input. Measured per screen-share segment the page is 0.58-2.11 MB, so a segment is the unit that publishes; a 58-minute video in one page still exceeds the cap and needs `--display-distance` (15.81 MB at 55, 13.35 MB at 70) or narrowing. Found by measuring the real command rather than trusting that the earlier `dedupe` fix covered both call sites — it did not.
- `screenscribe` (v0.2.0): piping a long `build` through `| tail` reports the exit status of `tail`, so a run that died on `DownloadError` was recorded as exit 0. Not a code change — a note for anyone verifying a build.

### Added
- `screenscribe` (v0.3.0, marketplace 1.23.0): **`bootstrap` subcommand — a fresh plugin install now provisions itself.** The skill previously resolved `$PY` to the venv *if it happened to exist* and otherwise fell back to a bare `python3` that had none of the dependencies; `build` then failed with a list of commands for the operator to run by hand and retry. On a fresh install that is the guaranteed first experience. `python3 screenscribe.py bootstrap` creates `~/.screenscribe/venv`, installs `yt-dlp`/`imagehash`/`pillow`/`curl_cffi`, and prints the interpreter path on stdout so SKILL.md binds it directly with `PY=$(python3 "$SC" bootstrap)`. It imports only the standard library, because on a fresh install nothing else is there to import. Idempotent: a second run installs nothing and prints only the path. Self-healing: a package removed from an existing venv is detected and reinstalled, so adding a dependency in a later release does not strand anyone. Optional packages are installed but never fatal — `curl_cffi` failing to build must not block a video — while a missing *required* package after install exits non-zero. `ffmpeg` and `deno` cannot be pip-installed and are reported as warnings with what each absence costs. pip's stdout is redirected to stderr: stdout carries exactly one thing, and a pip upgrade notice landing in it would silently corrupt `$PY`. Verified on a genuinely empty directory with system python3: venv created, all four packages installed, path bound, all four importable; second run silent; a deliberately uninstalled `imagehash` detected and healed. 7 tests (140 -> 147).
- `screenscribe` (v0.2.0): `curl_cffi` and `deno` added to the documented dependencies. Neither is imported by the script and neither is preflighted; yt-dlp uses them when present and warns when absent — "no impersonate target is available" means requests do not match a browser's TLS fingerprint and draw rate limits sooner, and "extraction without a JS runtime has been deprecated" means formats may not be offered at all, which can quietly defeat the 1080p selection this plugin depends on. Cookie authentication (`--cookies-from-browser`) is documented as the deliberate non-default: it makes requests look signed-in, but attaches the download to a real Google account that YouTube suspends for automated use, where impersonation carries no such risk.
- `screenscribe` (v0.2.0): **frames are now classified as screen content or camera footage**, because on conversational video the overwhelming majority carry no payload. Flatness — the fraction of near-white/near-black pixels in `HASH_BOX` — separates them: UI is flat white or flat dark with sharp text, a face is continuous midtone. Across 3165 frames of the podcast the distribution is **bimodal with an empty valley**: 1991 frames below 0.05, only 10 in the 0.10-0.25 band, 940 above. Any threshold inside that valley gives the same answer within 6 frames, so `CONTENT_FLATNESS = 0.19` is not a fitted constant. Labelled spot-checks over 16 hand-verified frames: every real screen scored >= 0.243, every face <= 0.127. Edge density and colour saturation were both measured and both **rejected** — the corner webcams contaminate every whole-frame metric (screen 0.114-0.121 vs face 0.096-0.101, with over half the population inside that gap), and saturation false-positived on faces against pale walls. Scores ride in `meta.json`; nothing is deleted, because extraction cannot know what a later read will want.
- `window` reads content frames by default and reports how many camera frames it hid; `--all` shows everything. A span containing **no** screen at all falls back to showing camera frames with an explicit note rather than returning empty — silence there would read as "the video has no footage here" instead of "no screen was shared here". A bundle built before classification existed has no scores and shows every frame, so old bundles are unaffected.
- **`BUNDLE.md` is now the scribe**, not just a navigation map: the transcript is interleaved with the frames that were on screen while each line was spoken. A `SCREEN` line names the frame, so `grep` for a term returns the narration *and* the picture path together, and `grep SCREEN` lists every screen in the video. A content frame with nothing said over it still gets a line — a silent screen is exactly the payload a transcript omits. No separate index file: frames are named `HH-MM-SS.jpg`, so any timestamp in the transcript already maps to its own frame, and a second copy of that mapping could only drift from the first. For the 58-minute video the whole scribe is ~34k tokens, so it fits in one read and the 245 MB of frames stay on disk for on-demand lookup.
- **Screen-share segments** and **derived sections**. Contiguous runs of content frames are recorded in `meta.json` and tabulated in `BUNDLE.md` with a per-span token estimate: the podcast carries 22m13s of screen across 17 spans, largest 176k tokens, so every span fits under the window cap and the whole video is readable span by span instead of not at all (3165 frames is ~4.7M tokens against a 1M context — it was never watchable). When the author published no chapters, boundaries are derived from those spans and labelled with the first words spoken over each, marked in the file as navigation only rather than the author's own outline.
- 28 tests for the above (95 -> 123), covering flatness bands, `HASH_BOX` geometry, corner-motion hashing in both modes, segment merge/split/minimum, derived-section labelling and truncation, the window filter with its `--all` and no-content fallback, and the interleaved BUNDLE.md.
- `screenscribe` (v0.1.1, marketplace 1.21.1): `bestvideo[height<=1080]` selected YouTube's premium vp9 stream, which pulled **over 1 GB** for a 58-minute video where the same title offers av01 at 587 MB with identical 1920x1080 pixels. Source *resolution* is load-bearing and source *bitrate* is not: frames are scaled to `FRAME_WIDTH` (1408), so a 1920-wide source is downscaled — a low-pass filter that discards exactly the high-frequency detail a high bitrate buys — while a 1280-wide source is **upscaled**, inventing pixels that were never there. Measured on a 1080p screen-share holding both body text and a diagram with near-sub-pixel labels, all three run through the real pipeline and read back as images: premium vp9 (>1 GB) and av01 (587 MB) are character-for-character identical, while 720p (265 MB) loses `spec/actions_specs/zip_spec.rb`, `bundle exec rspec` and `12 examples, 0 failures` entirely. Now `format_sort: ["res:1080", "+size", "+br"]` — resolution first, then the smallest encode of it. Verified across three videos: all still select 1920x1080, only the 58-minute one changes.
- Found by stress-testing a 58-minute video through the installed plugin: 7m15s wall clock, 3517 frames sampled -> 3165 kept, 245 MB bundle, `_staging` cleaned up, and the no-chapters path rendered without an empty heading. That run also surfaced a calibration issue **not** fixed here — retention was 89.99%, one frame under the >90% threshold that warns about whole-frame phash being defeated, and two circular face cams over a screen-share is precisely the case that warning exists for.

### Added
- `.gitignore`: Python ignores (`__pycache__/`, `*.py[cod]`, `.venv/`, `.pytest_cache/`, `.ruff_cache/`, `.mypy_cache/`, coverage output) and `bundles/`, since a screenscribe bundle runs roughly 100-240 MB per hour depending on how much the frame actually changes.
- `screenscribe` (v0.1.0, marketplace 1.21.0): new plugin — **automates the watching and the scribing** of a video, so Claude can write down what was actually on screen and build whatever you need from it: a spec, a review of the video, a summary, or the list of commands actually run. Every artifact cites re-openable `Watch:` spans rather than a remembered timestamp. Transcripts are the wrong artifact for a screencast: the payload is on screen (terminal commands, file trees, IDE state, diagrams) and the narration around it is filler. `scripts/screenscribe.py` has two modes. `build` samples the video at a configurable rate (default 1 fps, matching the granularity transcripts are cut at), drops visually-identical frames by perceptual hash, and names every survivor `HH-MM-SS.jpg`. `window <bundle> <start> <end>` reads a span back — printing bare absolute frame paths interleaved with the narration spoken over them — so the context budget is spent at **read** time by something that knows the question, rather than at extraction time by a heuristic that does not. A 10-minute span at 1 fps runs ~150k tokens, so a full-length tutorial is watchable in sections across one session. `BUNDLE.md` is a navigation map (chapters, per-minute frame density, full transcript) and deliberately inlines **no** frames: at 1 fps that file would be thousands of images long, and `![](frames/x.jpg)` in a file Claude reads is inert text that loads nothing. Specs emitted against `assets/spec-template.md` carry a `Watch:` span rather than a bare timestamp, so a disputed requirement is settled by re-opening the source; `references/spec-quality.md` requires every acceptance criterion to be runnable or observable (`cmd exits 0` beats "works correctly"), makes non-goals mandatory (agents creep scope because every adjacent improvement is defensible in isolation), and lists anything Claude inferred rather than the user stating it. Emit stays conversational and NOT automated: the video is a source of ideas, not a requirements document. Named `screenscribe` end to end — plugin, skill, and script — because the durable capability is watching and scribing; the spec is one consumer of the bundle, not the point of it. Stays at v0.1.0 / marketplace 1.21.0 through every rename and revision in this entry: none of it has been published, so this is all one unreleased change and the first release is the first thing anyone can install. Bundles default to `~/.screenscribe/bundles`, overridable by `$SCREENSCRIBE_BUNDLES` or `-o <path>`. The default sits under `$HOME` rather than the working directory because a bundle runs 100-240 MB: a cwd-relative default drops that into whatever repo the user is standing in and obliges every one of them to carry a `bundles/` gitignore entry, and one video informing three projects would be downloaded three times. with the env var set, `window` also accepts a bare video id, so a spec's `Watch:` line resolves from any working directory and one video informing several repos is downloaded once rather than per checkout. A direct path that is already a bundle always wins over the library. **First plugin in this marketplace with external dependencies** — `ffmpeg` on PATH plus `yt-dlp`/`imagehash`/`pillow`. 55 stdlib-`unittest` tests cover the VTT parser, frame sampling, dedupe, timestamp naming, and windowed read-back; those needing ffmpeg or Pillow skip themselves. **Validated end-to-end against a live YouTube tutorial** (a 7:24 git-rebase screencast): 29s wall clock, 138 transcript cues, 444 frames sampled -> 312 kept, 30 MB on disk, chapters extracted. Frames at 1408px were legible down to individual commit SHAs in a `git-rebase-todo` buffer and a full `git bisect` command sequence — both moments where the narration says nothing usable ("is S for a squash."), which is the thesis the plugin exists to serve.
  - **Path traversal fixed before release (found by adversarial review, reproduced end-to-end).** `fetch()` returned yt-dlp's `info["id"]` verbatim and `cmd_build` built the output directory from it with no validation. That id is network-derived, not a constrained token: for any URL falling through to yt-dlp's generic extractor it is `unquote(<last path segment>)`, so `https://host/..%2f..%2fwork.mp4` yields the literal id `../../work`. Confirmed against installed yt-dlp 2026.8.19 and reproduced with the real `cmd_build`: frames and `meta.json` were written outside `--out`, a pre-existing `BUNDLE.md` at the traversed location was overwritten, and `sample_frames`' `shutil.rmtree` **destroyed a directory named `frames`** there — the run then reported `[done]` and exit 0. YouTube ids are `[A-Za-z0-9_-]{11}` so the documented happy path never triggered it, but nothing restricted input to youtube.com. Now: the id is sanitized to one path segment, the destination is asserted to resolve inside the output root, and `sample_frames` refuses to clear any directory containing non-`.jpg` entries. Underscore is deliberately NOT stripped during sanitization — it is legal in a YouTube id, and stripping it renamed the bundle away from the id a spec's `Watch:` line cites.
  - Found by the live run: yt-dlp's `quiet: True` does not suppress its progress bar, which writes straight to stdout and garbled the script's own output — `noprogress: True` added. The README's disk estimate was recalibrated from synthetic frames to the real run: retention depends heavily on production style, and a webcam-behind-translucent-terminal layout defeats perceptual dedupe almost entirely (70% kept, ~240 MB/hour) where a static screencast dedupes far harder.
  - Fixed before release, all three found by executing the code rather than reading it: `next(staging.glob("video.*"))` also matched `video.en.vtt` and handed the **subtitle file** to ffmpeg — on APFS `scandir` returned it first, so stage 1 would have failed on every video that has captions. The VTT rolling-duplicate strip only caught exact repeats, but YouTube's auto-captions *extend* the previous cue rather than repeating it, so a real transcript came out ~2.4x duplicated; cues are now merged against a running word tail (word-based, so a tail ending in "back" does not eat the "back" of "backend"). And `imagehash.phash()` at its default `hash_size=8` — a 32x32 grayscale DCT — cannot see screencast text at all: across six distinct terminal scenes the distinct-scene hamming distances were 0, 0, 4, 6, 14 while identical frames scored 0, so **no threshold separates them** and the shipped default of 6 discarded three of five real transitions while reporting success. `hash_size=16` scores 26 minimum between distinct scenes and 0 within identical ones.
  - Design changes from the drafted version: fixed-rate sampling replaced ffmpeg's `select='gt(scene,N)'` plus `pts_time` stderr parsing, whose file/timestamp zip was load-bearing and silently misaligned the whole bundle on any ffmpeg version difference — frame N is now at `(N-1)/fps` arithmetically, which also recovers the `t=0` opening frame scene detection never emitted. `FRAME_WIDTH` 1280 → 1408: Claude downscales anything over ~1.15 MP, so 1408x792 is the widest frame whose pixels survive, and 1280 was giving away 21% of them. JPEG q3 kept over PNG after measuring SSIM 0.995 / PSNR 42.7 dB on h264-sourced terminal text — token cost is set by pixel dimensions, so PNG's 2.8x disk buys only a faithful copy of h264's own artifacts. The build-time cull to 60 frames was removed entirely; `window` enforces the budget instead.
  - `--gemini` was **cut before release** rather than ported. It emitted `extraction.md` — Gemini's already-compressed reading of the video — which is derived evidence that fails for the same reason a transcript does: a spec citing it cites a claim, where a spec citing a frame cites a source. It also carried the plugin's only API key, its only second vendor, and a code path that had never executed. Verified against Google's live docs in the process: the Interactions API went GA in June 2026 and `generate_content` is legacy-but-supported (so the call was stale, not broken), and the plan doc's claim that text goes *after* the video part contradicts the current YouTube example, which puts text first. `docs/plans/screenscribe-gemini-ingestion.md` records the decision and the follow-up worth building — let Gemini pick *which timestamps matter*, then cut frames there with ffmpeg and read the pixels ourselves.
  - The skill's internal `PLAN.md` was deleted rather than shipped — it was a working status file distributed to every installer. Its surviving open questions moved to `docs/plans/screenscribe-gemini-ingestion.md`. References to a `/goal` command were removed from both READMEs: no such command exists in this marketplace.
- `code-reviewer` (v2.9.0, marketplace 1.19.0): **Spec Coverage pass** for story-linked PRs. New `skills/code-reviewer/assets/spec-coverage-protocol.md` asset holds the authoritative protocol — acceptance-criteria parsing, PR-description checklist parsing, evidence verification (commit SHA / file:line / keyword grep), deferral verification, and YAML output shape. SKILL.md's new Phase 4.5 is calling-agent-only: it detects story-link via `gh issue view <N> --json labels`, resolves the story file (caller-provided `STORY_FILE`, local `docs/epics/*/.github-state.json` mapping, or GH issue body fallback), and **enriches each dispatched PE's input with `STORY_LINKED: true`, `STORY_FILE: <path>`, `SPEC_COVERAGE_PROTOCOL: <absolute path>`, `PR_NUMBER: <N>`.** All 5 PE agents (`pe-go`, `pe-vue`, `pe-aws-infra`, `pe-governance`, `pe-devtools`) gain a slim "Spec Coverage" section that triggers on `STORY_LINKED: true` by Reading the asset and following its protocol — producing `SPEC-MISSING-*`, `SPEC-EVIDENCE-MISSING-*`, `SPEC-DEFER-INVALID-*`, `SPEC-DEFER-CLOSED-*`, `SPEC-WEAK-EVIDENCE-*`, and `SPEC-FORMAT-*` findings alongside their stack findings. PEs may optionally annotate stack findings with `discharges_ac: ["AC-N"]` metadata. The asset-based design keeps the protocol authoritative in ONE file while ensuring the reviewer agents (who do NOT see SKILL.md) actually have access to it — addressing the architectural concern that placing reviewer-facing rules in SKILL.md leaves them invisible to the agents that need them. Multi-PE dispatch produces duplicate SPEC findings; Phase 4 de-duplication consolidates them. Non-story PRs (chores, bugfixes, tasks) keep the four-pass protocol unchanged. Motivated by the Corebizy Phase 5/6 incident where Story #1435 PRs shipped without integrating the Story #1443 hardening payload they were contracted to ship — narrow code change passed all four reviewer passes, story acceptance criteria were not verified, gap discovered downstream.

### Fixed
- `issue-manager` (1.0.5) and `session-analyzer` (1.0.3): the script resolver's fail-loud path did not survive `set -e`. `VAR=$(python3 -c "…")` where the python exits 1 kills the shell **at the assignment**, so the guard never ran and the `find ~/.claude/skills` manual-install fallback was dead code — an agent that prepends `set -euo pipefail` (routine) got a bare exit 1 with no message. Both command substitutions now end in `|| true`. The `find` one needs it too: `find` exits 1 when `~/.claude/skills` is absent, and that assignment is the final command of its `&&` list, so the `set -e` exemption for AND-lists does not cover it.
- `issue-manager` (1.0.5) and `session-analyzer` (1.0.3): matching on plugin name alone made resolution first-match-wins in JSON insertion order. With both the old and new marketplace identifiers present — the exact post-rename state — a stale entry pointing at an older cached version could win permanently and silently, and an unrelated marketplace shipping a same-named plugin could shadow this one. Entries from this marketplace now sort first, with any other marketplace as fallback.
- `issue-manager` (1.0.5) and `session-analyzer` (1.0.3): `entry.get('installPath', '')` turned a missing `installPath` into a **CWD-relative** path, so `.is_file()` was evaluated against whatever directory the skill happened to run in and could resolve — and then execute — an unrelated file with exit 0. Entries without `installPath` are skipped, and the resolved path must be absolute.
- `issue-manager` (1.0.5) and `session-analyzer` (1.0.3): a structurally malformed registry (`plugins` as a list, entries as a string) raised an uncaught `AttributeError` and dumped a traceback ahead of the real message, now that `2>/dev/null` is gone. The guard catches any exception and rejects a non-dict `plugins`.
- Dropped the "canonical — always points to the active version" claim from both SKILL.md files. The resolver never guaranteed that, and after the changes above it explicitly does not.
- `code-reviewer` (v2.7.3, marketplace 1.17.3): all 5 PE agent definitions (`pe-go`, `pe-vue`, `pe-aws-infra`, `pe-governance`, `pe-devtools`) now grant the full lifecycle toolkit. Previously each PE was granted only 8 tools (`Read, Write, Bash, Grep, Glob, SendMessage, WebSearch, WebFetch`) — designed as one-shot YAML returners with no lifecycle awareness. With team-mode dispatch, multi-round review protocols, and round-to-round continuity contracts, that 8-tool baseline is structurally insufficient. New baseline: `Read, Write, Edit, Bash, Grep, Glob, WebSearch, WebFetch, SendMessage, ScheduleWakeup, TaskCreate, TaskUpdate, TaskList, TaskGet, ToolSearch, Skill` (16 tools). Added: `Edit` (efficient diff-mode edits to review docs), `ScheduleWakeup` (lightweight one-shot polling for multi-round dispatch), `Task*` (receipt-per-tick contract enforcement), `ToolSearch` (deferred-tool introspection), `Skill` (composable skill invocation, e.g., for slack-messaging during review). Deliberately NOT added: `Cron*` (heavy, ScheduleWakeup sufficient), `Monitor` (silent-failure mode), `Team*` (reviewers should not create teams), `AskUserQuestion` (reviewers report findings via SendMessage, not interactive user prompts). Brings plugin PEs to feature parity with project-level engineering agents.
- `code-reviewer` (v2.7.2, marketplace 1.17.2): all 5 PE agent definitions (`pe-go`, `pe-vue`, `pe-aws-infra`, `pe-governance`, `pe-devtools`) now bake the team-mode delivery contract into their own Workflow step. Previously the contract lived only in the calling-agent dispatch input (SKILL.md), so PEs invoked from custom calling-agents that omitted the delivery clause would render YAML in session and idle without SendMessage. Now PE definitions self-contain the contract: `match invocation_mode: foreground → return YAML as tool-result; background-teammate → SendMessage(to: "team-lead", message: <yaml>)`. PEs deliver correctly regardless of dispatch site.
- `code-reviewer` (v2.7.1, marketplace 1.17.1): SKILL.md `§ Dispatch Input` now specifies an explicit DELIVERY CONTRACT split by invocation mode. Previously, "Return YAML findings" was ambiguous — when calling agents dispatched PEs with `team_name` set (background teammate mode), PEs would render YAML in their session and idle without calling the SendMessage tool, leaving the calling agent with no findings. Now: foreground dispatch returns YAML as tool-result; background-team dispatch delivers YAML via SendMessage to the team lead. Calling-agent contract clarified to treat team-mode dispatches as async with SendMessage delivery, not synchronous tool result.
