## [Unreleased]

### Fixed
- `screenscribe` (v0.1.1, marketplace 1.21.1): `bestvideo[height<=1080]` selected YouTube's premium vp9 stream, which pulled **over 1 GB** for a 58-minute video where the same title offers av01 at 587 MB with identical 1920x1080 pixels. Source *resolution* is load-bearing and source *bitrate* is not: frames are scaled to `FRAME_WIDTH` (1408), so a 1920-wide source is downscaled — a low-pass filter that discards exactly the high-frequency detail a high bitrate buys — while a 1280-wide source is **upscaled**, inventing pixels that were never there. Measured on a 1080p screen-share holding both body text and a diagram with near-sub-pixel labels, all three run through the real pipeline and read back as images: premium vp9 (>1 GB) and av01 (587 MB) are character-for-character identical, while 720p (265 MB) loses `spec/actions_specs/zip_spec.rb`, `bundle exec rspec` and `12 examples, 0 failures` entirely. Now `format_sort: ["res:1080", "+size", "+br"]` — resolution first, then the smallest encode of it. Verified across three videos: all still select 1920x1080, only the 58-minute one changes.
- Found by stress-testing a 58-minute video through the installed plugin: 7m15s wall clock, 3517 frames sampled -> 3165 kept, 245 MB bundle, `_staging` cleaned up, and the no-chapters path rendered without an empty heading. That run also surfaced a calibration issue **not** fixed here — retention was 89.99%, one frame under the >90% threshold that warns about whole-frame phash being defeated, and two circular face cams over a screen-share is precisely the case that warning exists for.

### Changed
- Repository moved to `lafollett-labs/lafollett-labs-claude-plugins` — transferred from the `clafollett` account to the org, then renamed to hyphenate `lafollett-labs` in line with the other company-scope repos. `.claude-plugin/marketplace.json` (5 `homepage` fields), all 5 `plugins/*/.claude-plugin/plugin.json` `repository` fields, and the README install line now point at the new URL. GitHub redirects both old paths, so an already-added marketplace keeps resolving (verified: `git ls-remote` against each old URL returns the same HEAD).
- **Marketplace identifier renamed** to `lafollett-labs-claude-plugins`, completing the alignment. Claude Code's marketplace namespace treats the two spellings as the **same key** — hyphens are filesystem-ignorable in its collision check — so `claude plugin marketplace add` refuses the new name while the old registration exists, even once `claude plugin marketplace list` has stopped showing it. If an install ends up in a mixed state, the recovery is `claude plugin marketplace remove lafollettlabs-claude-plugins`, then `add`, then `claude plugin install <plugin>@lafollett-labs-claude-plugins` for each of the five. Kept at a minor version rather than major: nothing that consumed the identifier is left broken, because the resolver fix below ships in the same release and reads both identifiers.
- `issue-manager` (1.0.4) and `session-analyzer` (1.0.2): script resolution no longer hardcodes the marketplace identifier. Both SKILL.md resolvers now match on the **plugin** name (`key.split('@')[0]`) rather than the full `plugin@marketplace` key, so they resolve under the old identifier and the new one — no migration window — and no future marketplace rename can orphan them. Resolution also now **fails loudly**: previously a miss yielded `{}`, the `KeyError` was swallowed by `2>/dev/null`, and the `find ~/.claude/skills` fallback only matched manual installs, so the skill carried on with an empty script path. It now writes to stderr and exits 1. The check uses `if`, not a trailing `[ -z ] && { … }` — a trailing test that is false returns 1, which reported failure on the success path.
- `.claude-plugin/marketplace.json`: dropped the unknown `metadata.license` field. `claude plugin validate` now passes with **zero** warnings, so the next real warning is visible instead of buried under a standing one. The MIT license is still declared in every `plugin.json` and in `LICENSE`.

### Added
- `.gitignore`: Python ignores (`__pycache__/`, `*.py[cod]`, `.venv/`, `.pytest_cache/`, `.ruff_cache/`, `.mypy_cache/`, coverage output) and `bundles/`, since a screenscribe bundle runs roughly 100-240 MB per hour depending on how much the frame actually changes.
- `screenscribe` (v0.1.0, marketplace 1.21.0): new plugin — **automates the watching and the scribing** of a video, so Claude can write down what was actually on screen and build whatever you need from it: a spec, a review of the video, a summary, or the list of commands actually run. Every artifact cites re-openable `Watch:` spans rather than a remembered timestamp. Transcripts are the wrong artifact for a screencast: the payload is on screen (terminal commands, file trees, IDE state, diagrams) and the narration around it is filler. `scripts/screenscribe.py` has two modes. `build` samples the video at a configurable rate (default 1 fps, matching the granularity transcripts are cut at), drops visually-identical frames by perceptual hash, and names every survivor `HH-MM-SS.jpg`. `window <bundle> <start> <end>` reads a span back — printing bare absolute frame paths interleaved with the narration spoken over them — so the context budget is spent at **read** time by something that knows the question, rather than at extraction time by a heuristic that does not. A 10-minute span at 1 fps runs ~150k tokens, so a full-length tutorial is watchable in sections across one session. `BUNDLE.md` is a navigation map (chapters, per-minute frame density, full transcript) and deliberately inlines **no** frames: at 1 fps that file would be thousands of images long, and `![](frames/x.jpg)` in a file Claude reads is inert text that loads nothing. Specs emitted against `assets/spec-template.md` carry a `Watch:` span rather than a bare timestamp, so a disputed requirement is settled by re-opening the source; `references/spec-quality.md` requires every acceptance criterion to be runnable or observable (`cmd exits 0` beats "works correctly"), makes non-goals mandatory (agents creep scope because every adjacent improvement is defensible in isolation), and lists anything Claude inferred rather than the user stating it. Emit stays conversational and NOT automated: the video is a source of ideas, not a requirements document. Named `screenscribe` end to end — plugin, skill, and script — because the durable capability is watching and scribing; the spec is one consumer of the bundle, not the point of it. Stays at v0.1.0 / marketplace 1.21.0 through every rename and revision in this entry: none of it has been published, so this is all one unreleased change and the first release is the first thing anyone can install. Bundles default to `~/.screenscribe/bundles`, overridable by `$SCREENSCRIBE_BUNDLES` or `-o <path>`. The default sits under `$HOME` rather than the working directory because a bundle runs 100-240 MB: a cwd-relative default drops that into whatever repo the user is standing in and obliges every one of them to carry a `bundles/` gitignore entry, and one video informing three projects would be downloaded three times. with the env var set, `window` also accepts a bare video id, so a spec's `Watch:` line resolves from any working directory and one video informing several repos is downloaded once rather than per checkout. A direct path that is already a bundle always wins over the library. **First plugin in this marketplace with external dependencies** — `ffmpeg` on PATH plus `yt-dlp`/`imagehash`/`pillow`. 55 stdlib-`unittest` tests cover the VTT parser, frame sampling, dedupe, timestamp naming, and windowed read-back; those needing ffmpeg or Pillow skip themselves. **Validated end-to-end against a live YouTube tutorial** (a 7:24 git-rebase screencast): 29s wall clock, 138 transcript cues, 444 frames sampled -> 312 kept, 30 MB on disk, chapters extracted. Frames at 1408px were legible down to individual commit SHAs in a `git-rebase-todo` buffer and a full `git bisect` command sequence — both moments where the narration says nothing usable ("is S for a squash."), which is the thesis the plugin exists to serve.
  - **Path traversal fixed before release (found by adversarial review, reproduced end-to-end).** `fetch()` returned yt-dlp's `info["id"]` verbatim and `cmd_build` built the output directory from it with no validation. That id is network-derived, not a constrained token: for any URL falling through to yt-dlp's generic extractor it is `unquote(<last path segment>)`, so `https://host/..%2f..%2fwork.mp4` yields the literal id `../../work`. Confirmed against installed yt-dlp 2026.8.19 and reproduced with the real `cmd_build`: frames and `meta.json` were written outside `--out`, a pre-existing `BUNDLE.md` at the traversed location was overwritten, and `sample_frames`' `shutil.rmtree` **destroyed a directory named `frames`** there — the run then reported `[done]` and exit 0. YouTube ids are `[A-Za-z0-9_-]{11}` so the documented happy path never triggered it, but nothing restricted input to youtube.com. Now: the id is sanitized to one path segment, the destination is asserted to resolve inside the output root, and `sample_frames` refuses to clear any directory containing non-`.jpg` entries. Underscore is deliberately NOT stripped during sanitization — it is legal in a YouTube id, and stripping it renamed the bundle away from the id a spec's `Watch:` line cites.
  - Found by the live run: yt-dlp's `quiet: True` does not suppress its progress bar, which writes straight to stdout and garbled the script's own output — `noprogress: True` added. The README's disk estimate was recalibrated from synthetic frames to the real run: retention depends heavily on production style, and a webcam-behind-translucent-terminal layout defeats perceptual dedupe almost entirely (70% kept, ~240 MB/hour) where a static screencast dedupes far harder.
  - Fixed before release, all three found by executing the code rather than reading it: `next(staging.glob("video.*"))` also matched `video.en.vtt` and handed the **subtitle file** to ffmpeg — on APFS `scandir` returned it first, so stage 1 would have failed on every video that has captions. The VTT rolling-duplicate strip only caught exact repeats, but YouTube's auto-captions *extend* the previous cue rather than repeating it, so a real transcript came out ~2.4x duplicated; cues are now merged against a running word tail (word-based, so a tail ending in "back" does not eat the "back" of "backend"). And `imagehash.phash()` at its default `hash_size=8` — a 32x32 grayscale DCT — cannot see screencast text at all: across six distinct terminal scenes the distinct-scene hamming distances were 0, 0, 4, 6, 14 while identical frames scored 0, so **no threshold separates them** and the shipped default of 6 discarded three of five real transitions while reporting success. `hash_size=16` scores 26 minimum between distinct scenes and 0 within identical ones.
  - Design changes from the drafted version: fixed-rate sampling replaced ffmpeg's `select='gt(scene,N)'` plus `pts_time` stderr parsing, whose file/timestamp zip was load-bearing and silently misaligned the whole bundle on any ffmpeg version difference — frame N is now at `(N-1)/fps` arithmetically, which also recovers the `t=0` opening frame scene detection never emitted. `FRAME_WIDTH` 1280 → 1408: Claude downscales anything over ~1.15 MP, so 1408x792 is the widest frame whose pixels survive, and 1280 was giving away 21% of them. JPEG q3 kept over PNG after measuring SSIM 0.995 / PSNR 42.7 dB on h264-sourced terminal text — token cost is set by pixel dimensions, so PNG's 2.8x disk buys only a faithful copy of h264's own artifacts. The build-time cull to 60 frames was removed entirely; `window` enforces the budget instead.
  - `--gemini` was **cut before release** rather than ported. It emitted `extraction.md` — Gemini's already-compressed reading of the video — which is derived evidence that fails for the same reason a transcript does: a spec citing it cites a claim, where a spec citing a frame cites a source. It also carried the plugin's only API key, its only second vendor, and a code path that had never executed. Verified against Google's live docs in the process: the Interactions API went GA in June 2026 and `generate_content` is legacy-but-supported (so the call was stale, not broken), and the plan doc's claim that text goes *after* the video part contradicts the current YouTube example, which puts text first. `docs/plans/screenscribe-gemini-ingestion.md` records the decision and the follow-up worth building — let Gemini pick *which timestamps matter*, then cut frames there with ffmpeg and read the pixels ourselves.
  - The skill's internal `PLAN.md` was deleted rather than shipped — it was a working status file distributed to every installer. Its surviving open questions moved to `docs/plans/screenscribe-gemini-ingestion.md`. References to a `/goal` command were removed from both READMEs: no such command exists in this marketplace.
- `code-reviewer` (v2.9.0, marketplace 1.19.0): **Spec Coverage pass** for story-linked PRs. New `skills/code-reviewer/assets/spec-coverage-protocol.md` asset holds the authoritative protocol — acceptance-criteria parsing, PR-description checklist parsing, evidence verification (commit SHA / file:line / keyword grep), deferral verification, and YAML output shape. SKILL.md's new Phase 4.5 is calling-agent-only: it detects story-link via `gh issue view <N> --json labels`, resolves the story file (caller-provided `STORY_FILE`, local `docs/epics/*/.github-state.json` mapping, or GH issue body fallback), and **enriches each dispatched PE's input with `STORY_LINKED: true`, `STORY_FILE: <path>`, `SPEC_COVERAGE_PROTOCOL: <absolute path>`, `PR_NUMBER: <N>`.** All 5 PE agents (`pe-go`, `pe-vue`, `pe-aws-infra`, `pe-governance`, `pe-devtools`) gain a slim "Spec Coverage" section that triggers on `STORY_LINKED: true` by Reading the asset and following its protocol — producing `SPEC-MISSING-*`, `SPEC-EVIDENCE-MISSING-*`, `SPEC-DEFER-INVALID-*`, `SPEC-DEFER-CLOSED-*`, `SPEC-WEAK-EVIDENCE-*`, and `SPEC-FORMAT-*` findings alongside their stack findings. PEs may optionally annotate stack findings with `discharges_ac: ["AC-N"]` metadata. The asset-based design keeps the protocol authoritative in ONE file while ensuring the reviewer agents (who do NOT see SKILL.md) actually have access to it — addressing the architectural concern that placing reviewer-facing rules in SKILL.md leaves them invisible to the agents that need them. Multi-PE dispatch produces duplicate SPEC findings; Phase 4 de-duplication consolidates them. Non-story PRs (chores, bugfixes, tasks) keep the four-pass protocol unchanged. Motivated by the Corebizy Phase 5/6 incident where Story #1435 PRs shipped without integrating the Story #1443 hardening payload they were contracted to ship — narrow code change passed all four reviewer passes, story acceptance criteria were not verified, gap discovered downstream.

### Fixed
- `issue-manager` (1.0.5) and `session-analyzer` (1.0.3): the script resolver's fail-loud path did not survive `set -e`. `VAR=$(python3 -c "…")` where the python exits 1 kills the shell **at the assignment**, so the guard never ran and the `find ~/.claude/skills` manual-install fallback was dead code — an agent that prepends `set -euo pipefail` (routine) got a bare exit 1 with no message. Both command substitutions now end in `|| true`. The `find` one needs it too: `find` exits 1 when `~/.claude/skills` is absent, and that assignment is the final command of its `&&` list, so the `set -e` exemption for AND-lists does not cover it.
- `issue-manager` (1.0.5) and `session-analyzer` (1.0.3): matching on plugin name alone made resolution first-match-wins in JSON insertion order. With both the old and new marketplace identifiers present — the exact post-rename state — a stale entry pointing at an older cached version could win permanently and silently, and an unrelated marketplace shipping a same-named plugin could shadow this one. Entries from this marketplace now sort first, with any other marketplace as fallback.
- `issue-manager` (1.0.5) and `session-analyzer` (1.0.3): `entry.get('installPath', '')` turned a missing `installPath` into a **CWD-relative** path, so `.is_file()` was evaluated against whatever directory the skill happened to run in and could resolve — and then execute — an unrelated file with exit 0. Entries without `installPath` are skipped, and the resolved path must be absolute.
- `issue-manager` (1.0.5) and `session-analyzer` (1.0.3): a structurally malformed registry (`plugins` as a list, entries as a string) raised an uncaught `AttributeError` and dumped a traceback ahead of the real message, now that `2>/dev/null` is gone. The guard catches any exception and rejects a non-dict `plugins`.
- Dropped the "canonical — always points to the active version" claim from both SKILL.md files. The resolver never guaranteed that, and after the changes above it explicitly does not.
- `code-reviewer` (v2.7.3, marketplace 1.17.3): all 5 PE agent definitions (`pe-go`, `pe-vue`, `pe-aws-infra`, `pe-governance`, `pe-devtools`) now grant the full lifecycle toolkit. Previously each PE was granted only 8 tools (`Read, Write, Bash, Grep, Glob, SendMessage, WebSearch, WebFetch`) — designed as one-shot YAML returners with no lifecycle awareness. With team-mode dispatch, multi-round review protocols, and round-to-round continuity contracts, that 8-tool baseline is structurally insufficient. New baseline: `Read, Write, Edit, Bash, Grep, Glob, WebSearch, WebFetch, SendMessage, ScheduleWakeup, TaskCreate, TaskUpdate, TaskList, TaskGet, ToolSearch, Skill` (16 tools). Added: `Edit` (efficient diff-mode edits to review docs), `ScheduleWakeup` (lightweight one-shot polling for multi-round dispatch), `Task*` (receipt-per-tick contract enforcement), `ToolSearch` (deferred-tool introspection), `Skill` (composable skill invocation, e.g., for slack-messaging during review). Deliberately NOT added: `Cron*` (heavy, ScheduleWakeup sufficient), `Monitor` (silent-failure mode), `Team*` (reviewers should not create teams), `AskUserQuestion` (reviewers report findings via SendMessage, not interactive user prompts). Brings plugin PEs to feature parity with project-level engineering agents.
- `code-reviewer` (v2.7.2, marketplace 1.17.2): all 5 PE agent definitions (`pe-go`, `pe-vue`, `pe-aws-infra`, `pe-governance`, `pe-devtools`) now bake the team-mode delivery contract into their own Workflow step. Previously the contract lived only in the calling-agent dispatch input (SKILL.md), so PEs invoked from custom calling-agents that omitted the delivery clause would render YAML in session and idle without SendMessage. Now PE definitions self-contain the contract: `match invocation_mode: foreground → return YAML as tool-result; background-teammate → SendMessage(to: "team-lead", message: <yaml>)`. PEs deliver correctly regardless of dispatch site.
- `code-reviewer` (v2.7.1, marketplace 1.17.1): SKILL.md `§ Dispatch Input` now specifies an explicit DELIVERY CONTRACT split by invocation mode. Previously, "Return YAML findings" was ambiguous — when calling agents dispatched PEs with `team_name` set (background teammate mode), PEs would render YAML in their session and idle without calling the SendMessage tool, leaving the calling agent with no findings. Now: foreground dispatch returns YAML as tool-result; background-team dispatch delivers YAML via SendMessage to the team lead. Calling-agent contract clarified to treat team-mode dispatches as async with SendMessage delivery, not synchronous tool result.
